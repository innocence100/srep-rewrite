# CLI automatic resource defaults (approved design summary)

This implementation is the scoped CLI portion of the reviewed D030 rev-5 design. It
changes only `srep compress` defaults; library `ResourceConfig::default()` and
decompress/test/info policies remain fixed. Archive format, compression algorithms,
atomic publication, and resource-accounting ledgers are unchanged.

## Compression memory

When `--memory` is absent, use half of total physical RAM, bounded by the minimum
identified visible cgroup hard limit (also halved). Physical RAM comes from Linux
`MemTotal`, macOS's fallible total-memory API, or Windows `Snapshot::get().total`.
Linux visible v1/v2 limits are aggregated by minimum while missing or malformed
expected levels remain indeterminate. Indeterminate detection uses a conservative
`min(256 MiB, physical/2 when known, known hard limit/2 when known)` fallback.
Unavailable/invalid physical detection uses the 256 MiB fallback, further bounded
by a known finite hard limit. Zero results are rejected by existing configuration
validation. Explicit `--memory` skips all probes. These budgets describe managed
compression working memory, not total RSS or a process/container hard cap.

## Temporary storage

Without `--temp-limit`, regular file inputs receive `max(32 GiB, input_length * 10)`;
checked multiplication overflow fails before staging and asks for explicit
`--temp-limit`. Stdin and non-regular files use 32 GiB. A regular input is opened
once after existing collision/output checks; metadata and reads use that handle.
Explicit `--temp-limit` skips metadata-based policy. No free-space startup check is
performed; the existing budget writer and filesystem errors remain authoritative.

## Diagnostics and retained behavior

Non-quiet compression reports the resolved byte values and independent `auto`,
`explicit`, or `fallback` origins on stderr. Fallback warnings are always emitted,
including in quiet mode; stdout archive output is untouched. Windows Job Objects,
macOS container limits, RLIMIT_AS, hidden cgroup ancestors, and competition for
physical RAM are outside this best-effort policy. Linux reports uncertainty rather
than guessing that missing visible cgroup files imply an unlimited host.

The production orchestration resolves, applies, validates, and reports resource
settings, then calls a transaction closure. That closure owns the reader, destination,
force setting, staging writer, and the pre-existing atomic finish/publish route; the
resource helper owns no sink.
