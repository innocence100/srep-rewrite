## Memory contract note

The managed `--memory` budget covers working state only: input/output buffers,
candidate storage, indexes, sorting, WIS/match selection, caches, and their
associated control state. The loaded verifier bytes and the input-hash buffer are
data-sized working state and remain charged; they are explicitly not pathname
metadata. File pathname processing (configured `temp_dir`, resolved absolute
parent, per-file `PathBuf`/`TempPath`) is excluded, so path length does not
consume the working budget and cannot itself cause a memory-policy rejection.
Additional resident memory beyond `--memory` can come from pathname processing,
runtime and allocator overhead.

## Scope and evidence

Only internally generated m3, including its configured m0 overlay, uses two
enumerations. External candidate APIs, even with method=m3, and internal m0/m1/
m2/m4/m5 retain the ordinary canonical-triple validation route.
Sample03 m3 has16,585,317 distinct triples,132,337 destination intervals and
724,706,858,496 candidate bytes to validate. Its64-byte triple table is
1,061,460,288 bytes (about1.061GB decimal,0.989GiB): it exceeds the unchanged
256MiB RAM/temp probe, but does **not** exceed1GiB in binary units. The
`tests/fixed_performance.rs` helper sets `temp_limit=memory=256MiB`; the CLI
default `temp_limit` is4GiB. The clarified release objective is bounded RAM,
with an independently configured adequate temp budget permitted for long or
spill-heavy runs. Every run still has an explicit positive `temp_limit`, and
must enforce disk-space, cleanup, file-count and FD safety. No RAM budget,
quality/byte-identity threshold, or candidate semantics may be weakened.

## Normative phases and errors

1. Validate configuration, admit session/verifier resources and spool input.
   Record original successful input writes' length/BLAKE3 identity, never adopt
   an expected digest by rereading disk.
2. Authenticate the actual loaded verifier snapshot against that identity before
   exposing exact forward LCE. Optional memory denial falls back to authenticated
   bytes or original periodic file checking. Actual I/O/corruption/cancellation
   never becomes optional denial. File fallback verifies uncached identity first.
3. Pass1 validates EVERY unreduced emitted row. Keep only the semantic error with
   smallest `(src,dst,len,ordinal)` in a bounded fixed-category witness. Structural
   overflow/interval/source-span checks precede len<=25 omission; minimum/bytes
   follow. No interval reduction or sort allocation in this pass.
4. Generator, verifier physical I/O, source-index, resource and cancellation errors
   fail immediately, even if semantic failure is pending. Complete base then
   optional overlay source barriers; combine phases, then verify input uncached.
   Only afterward return pending semantic failure. With none, issue V1 certificate.
5. Consume certificate after checking input/session/min/config/epoch. Drop pass1
   verifier; verify input before pass2. Re-enumerate into bounded interval sorter,
   hashing ALL rows before reduction. Complete source barriers, compare transcript,
   verify input uncached, then finalize interval/end stores. Any error precedes WIS.
6. Finish generation ONCE after both epochs; release source workspaces and enter
   unchanged WIS/selected store/writer/publication.

No equivalence is claimed between different physical-failure injection schedules.
When physical work succeeds the canonical semantic failure must equal the old
validator. A pending semantic error prevents every pass2 allocation.

## R4-A integration disposition (documentation checkpoint)

The clarified target is **RAM boundedness first**, not a requirement that every
workload fit inside the default temporary-space allowance. The fixed-performance
fixture remains a deliberately strict `256MiB RAM + 256MiB temp` probe. The CLI
default remains4GiB temp, while a later acceptance run may select a separately
documented, adequate temp directory/limit without raising the256MiB RAM limit.
That choice does not waive explicit `temp_limit` admission, single-file and
disk-space checks, FD/file-count limits, cleanup barriers, or durable peak
telemetry. A run that exhausts its configured temp or cleanup safety is a
resource failure, not permission to grow RAM or weaken semantics.

The implemented internal m3 path is retained for the next serial integration
review rather than simplified or deleted. This is the least disruptive route
because it directly addresses the measured obstruction without candidate
heuristics: pass1 validates every emitted row; pass2 hashes and replays every
unreduced emission, then performs only the authoritative interval reduction;
the certificate binds the authenticated input, configuration, session and
transcript; and the route is restricted to internally generated m3, with or
without the configured m0 overlay. External candidates and non-m3 methods stay
on the ordinary canonical-triple path. Exact triples remain available until
authoritative validation is complete, WIS's full lexicographic tie contract and
NGv3 bytes are unchanged, and no quality optimization is introduced.

This disposition is not an implementation review or acceptance claim. The
source review service was unavailable in R3, so the parent serial integration
owner must review `src/offload/normalize/m3.rs` and its wiring before release.
In particular, review the pass2 representative-cache eviction/replay proof,
transcript and phase barriers, authenticated input checks, simultaneous RAM and
temp reservations, and cleanup behavior under disk/FD failures. The R3 Linux
evidence is retained as historical evidence only; the real72-row fidelity,
258MiB default-m3, release-build and native-platform gates remain open.

## Exact verifier

For d=dst-src, periodic equality is equivalent to exact equality of
`input[src..src+min(len,d)]` with `input[dst..dst+min(len,d)]`, and if len>d,
`input[dst..dst+len-d]` with `input[dst+d..dst+len]`. The first establishes the first
period; the second propagates equality by induction. Use exact suffix/LCP queries,
never rolling-hash positives or uniform-seed/source-grid assumptions.
Forward verifier only: no reverse LCE, prefix/power/run tables. At512KiB input,
audited requested construction payload18.5MiB, retained6.5MiB. Actual capacities,
transient peaks, buffers/handles and simultaneously live finder caches remain
charged to the shared parent.16MiB snapshot cap; bounded file fallback above it.

## Identity, certificate and transcript

Trusted input digest is BLAKE3-256 of `SREP-OFF-INPUT-v1\0 || successful original
bytes || len:u64LE`. The immutable loaded bytes themselves must match it. Physical
length checks and fresh complete input verification surround both passes; persistent
mutation fails as ChecksumMismatch, not a misleading pending InvalidMatch.
Same-user hostile mutate/restore races or in-process trusted-state replacement
are outside this integrity model. Hashes guard integrity, not candidate equality.

V1 privately constructs non-Clone/non-Copy certificate binding SessionId, checked
epoch serial, original input identity, effective minimum, full semantic config,
transcript digest/count and completed phases. Config includes method,block,min,seed,
target,global distance,overlay presence/distance/min,effective values,layout,
checksum,flags; resource paths/budgets do not change emission identity. Certificate
is not constructible from a finder boolean or an unchecked representative store.

Transcript domain `SREP-OFF-M3-ENUM-v1\0`,version:u16LE, config and input identity;
fixed96-byte zero-padded events: BeginPhase(tag1,phase/method,start at8), Candidate
(tag2,phase/method,src/dst/len/ordinal at8/16/24/32,provenance at40/41), EndPhase
(tag3,start/next/count at8/16/24), EndEnumeration(tag4,total/final-next/phases at8/
16/24). Hash every emission including duplicates before sorting. Parent supplies
phase markers after actual enumeration/barriers; finders see only CandidateSink.

## Ownership and required regressions

B0 owns trusted spool identity and one-way epoch states; V1 owns pending witness,
verifier,certificate,replay sink and opaque ScheduleInput. W1 accepts prepared
ScheduleInput without changing WIS. Source loans are reused only after consuming
verified base/overlay barriers; no poison/cancel/counter/generation reset. Failed
first pass cannot begin second; missing/forged phase completion cannot publish.

Required tests: exhaustive independent periodic-byte/LCE equality, canonical
semantic permutations/duplicates, physical-vs-pending-error matrix, actual loaded
view corruption, input mutation across passes, wrong certificate session/input/
minimum/config, transcript count/order/ordinal/provenance/phase changes, real
base/overlay reuse, denial in either pass, no pass2 allocation after semantics
fail, unchanged external/non-m3 routes, unchanged sample03 debug/release gate and
selected IR/archive identity. Full72-row/258MiB/native/release gates remain later.
