Decisions (no user clarification required):

* Preserve NGv3 bytes, matching semantics, WIS objective and public raw APIs.
* Bound the **whole compression path**, including input staging, finders,
  candidate reduction, scheduling, selected metadata, source ordering, writer,
  file handles and temp bookkeeping. No candidate-only completion claim. The
  managed budget covers working state; file pathname processing (configured and
  resolved paths) and runtime/allocator overhead are excluded, so the budget is
  not a cap on total process RSS.
* Use existing Rust 1.88-compatible std, `tempfile`, `getrandom`, `blake3` and
  existing checksums. Keep `#![forbid(unsafe_code)]`; no mmap, database, new crate,
  persistent recovery format or external-sort subprocess.
* External runs + append-only fixed-record tables, not an on-disk balanced tree.
  The primary boundedness target is the shared RAM ledger. Temporary storage is
  independently configured: a larger adequate `temp_limit` is acceptable for
  spill-heavy workloads, but it remains explicit and enforced, with bounded
  file/FD counts, single-file limits, cleanup barriers and measured disk peaks.
* Use exact **linear-depth, constant-memory tie comparison** (§7), not baseline's
  quadratic-depth traversal and not binary lifting in the first implementation.
* Separate a private per-operation resource session from public ResourceConfig
  and ResourceContext. Both public structs currently support struct literals;
  adding a field to either would break callers. No hidden global registry.
* Public raw finders, public normalizers and match inspection remain explicitly
  RAM-returning and may return MemoryBudgetExceeded. CLI/library compression is
  the offload guarantee; unbounded successful decoding of every possible future
  archive is not silently included (reader risks and roundtrip gates in §9).
* All baseline-correct outputs retain exact bytes. An actual baseline bug must
  be isolated with a witness and reviewed, not copied as an oracle or hidden by
  changing goldens. No quality optimizer is smuggled into offload.

## 3. Precise semantic and failure contract

Let raw semantic candidate be `(src,dst,len,insertion_ordinal)` (all u64). Method
and phase provenance below are diagnostics only; never add them to WIS keys.

1. Validate config before input reads; enforce existing spool length/output/temp
   errors. Consume the candidate iterator/generator before semantic validation,
   as the existing collection stage does. Early transport/resource failure stops
   collection. Infinite iterators are not promised termination.
2. Canonicalize exact triples in `(src,dst,len,ordinal)` order, keeping minimum
   ordinal. This is the **only** reduction permitted before authoritative bytes
   validation, apart from bounded exact-triple suppression that retains that min.
3. For each canonical triple, in that order: checked dst+len (destination
   overflow); then src>=dst, end>input_len or src>=input_len (invalid interval).
   For len<=25, stop validation of that row here: it has no positive gain, no
   min-match/byte check, but an invalid interval must still fail. Otherwise reject
   len<effective_min, then validate every destination byte against periodic source
   `input[src + (offset % (dst-src))]`. Preserve existing message contexts for
   these errors. A bad row cannot hide behind a valid smaller-src `(dst,len)` row.
4. After **all** canonical rows pass, discard nonpositive-gain rows. Apply the
   normalizer's structural checked source span rule as well (logically implied
   by src<dst and valid end, but retain checked arithmetic and tests).
5. Sort `(dst,len,src,ordinal)` and keep first for each `(dst,len)`. The proof is
   exact: same occupied interval, weight, covered length and count; smaller src
   then ordinal is preferred wherever inserted into any chain. Different lengths
   MUST remain. No containment, longest-per-dst, grid or uniform-run deletion.
6. Sort `(checked_end,dst,src,Reverse(len),ordinal)` for scheduling. All sums and
   positions checked; use tuple comparators, not arithmetic subtraction tricks.
7. WIS: maximize sum(len-25), then covered bytes, then minimize match count, then
   lexicographically minimize the **whole forward chain** of
   `(dst,src,Reverse(len),ordinal)`. Equal chains choose exclude, as baseline.
   End<=next destination is compatible. No maximum-distance filtering here.
8. Assign origin_match_id=0..K-1 in destination order. Selected intervals are
   positive-length and disjoint; forward chain order already equals destination
   order. Checked covered sum and input_len-covered. Then preserve writer's
   selected-match checks including max_distance, which applies only to selected
   rows in the public candidate API. Do not reject an unselected far row earlier.

**Precedence boundaries:** semantic errors with readable stores and sufficient
resources must be identical across RAM/spill partitioning. During collection,
actual generator/I/O/ordinal errors may precede future row errors, just as RAM
collection errors did. An actual failing disk operation cannot be postponed to
discover a later semantic error; never manufacture a memory error instead of the
observed integrity/I/O error. New interval-sort output allocation must not mask a
later invalid candidate: complete a validation pass over the sealed triple store
before constructing interval runs (one extra sequential replay is intentional).
Validate sealed run envelopes/records/order before semantic pass so internal
corruption is not mistaken for a user invalid-match error. No claim of identical
error selection under different injected physical failures.

Exception explicitly proposed for review, not hidden as timing-equivalent:
private source-index queries no longer scan untouched records before each
callback. They use immutable construction validation, checked reads and an
uncached retirement/final integrity barrier (§6.1). Persistent unqueried-page
corruption is still rejected before any public archive copy, but may be observed
later than the baseline's next query, or be preceded by another terminal error.
Public CandidateIndex retains its existing stronger per-query scan contract.
If review requires identical private per-query corruption timing, this proposal
is BLOCKED on a different algorithm/contract; a cache cannot prove an externally
mutable file unchanged without reading it. Semantic row priority is unchanged.

Public normalizers have their own input-order structural-validation behavior;
leave that API unchanged. The private compression normalizer receives a validated
store, not arbitrary caller rows. Tests distinguish these two entry-point contracts.

layout. ReplayStore/cursor creation and read_at may use private RefCell-protected
I/O because the pipeline is serial; no unsafe, no borrow held across a callback,
and no Send/Sync promise added. Mutable append table belongs solely to WIS;
immutable tables provide fallible replay/random reads. Constructor policy and
owned reservations are not detached from the returned table. `finish` rejects
summary mismatch and seals before returning; zero-match summary is valid.

All cursor control objects and boxes are fixed in number and charged; never return
`Iterator<Item=T>` for disk rows without fallibility. Counts and row marks use
u64, checked usize only for bounded resident slices. cursor(EOF) succeeds;

Separate cursors have independent **logical** positions. Backend may serialize
seek/read through a single owned File, so no unbounded descriptor-per-cursor
rule; private cursor count capped (4 per store is sufficient here).

## 5. Storage and external sorting

### 5.1 Private fixed format, version 1

No native struct serialization or usize in files. All integers little-endian.
Use existing BLAKE3 incremental hasher truncated to 16 bytes for internal integrity
(not archive checksum); fixed domain separators for headers and records. These
are accidental corruption/cross-file mixup checks, not authentication against an
attacker running as the same user and recomputing checksums.

**128-byte header:**

| Offset | Size | Meaning |
|---|---:|---|
| 0 | 8 | magic `SRPOFF01` |
| 8 | 2 | format version=1 |
| 10 | 2 | header length=128 |
| 12 | 2 | record length for kind |
| 14 | 1 | kind (candidate, DP, match, reverse-index; private source pages in §6.1) |
| 15 | 1 | order (triple, interval, end, destination, source, append/reverse) |
| 16 | 8 | monotonically allocated generation within session |
| 24 | 8 | sealed row count |
| 32 | 8 | checked payload byte length=count*record_len for fixed-row kinds; §6.1 for source pages |
| 40 | 8 | flags: sealed=1; other bits zero |
| 48 | 16 | random session identity |
| 64 | 16 | random file identity |
| 80 | 8 | input length (zero for generic tests) |
| 88 | 24 | reserved zero |
| 112 | 16 | BLAKE3-128(`SREP-OFF-HDR-v1\0` || bytes[0..112]) |

**64-byte candidate record:** 0..8 src, 8..16 dst, 16..24 len,
24..32 insertion_ordinal, 32 method, 33 phase, 34..40 zero, 40..48 physical
row sequence, 48..64 checksum of domain `SREP-OFF-CAND-v1\0`, session/file
identities, generation, kind/order, and bytes[0..48]. Re-encode sequence and
checksum on every output run, preserving the four semantic fields. No redundant
stored end; compute checked end only after validation. Never reject malformed
user src/dst/len at serialization time; they are legal transport u64s.

**64-byte Match record:** 0..32 four Match u64s, 32..40 zero, 40..48 row sequence,
48..64 similarly bound checksum with MATCH domain. **96-byte DP row:**
0 gain, 8 covered, 16 count, 24 best_node, 32 include_parent, 40 include_depth,
48..72 zero, 72 row sequence, 80..96 bound checksum (all fields before checksum
in 8-byte slots). Candidate index i corresponds to DP row i. `u64::MAX` is null;
valid indices strictly below it. `best_node` is best[i+1]'s tail; include_parent
is best[p]'s tail for candidate i even if excluded. **32-byte reverse-index row:**
candidate_index at 0, sequence at 8, checksum at 16. File headers fix kind/width.

Envelope verification: exact expected length, count, flags, version, zero
padding, expected input/session/file/generation/order, per-row sequence/checksum,
sorted-order monotonicity, and typed invariants. Swapping valid records or entire
files must fail. Reject truncation and extra trailing bytes. Random reads validate
records before use and bounds before seek; no silent `unwrap_or(0)` on bad links.
Cache identity includes kind/generation/file/page. Reopened files verify header
identity before reading. Semantic sort keys are **decoded numeric tuples**, not
memcmp of LE bytes. Total tie ordering may use provenance only after all semantic
fields equal; it must never affect retained candidate semantics.

Build states: Writing -> Sealed -> Retired. Header initially unsealed; flush all
records then write sealed header/flush; only then publish its owning handle to
consumers. Errors drop the unsealed object. No per-run fsync needed: scratch is
single-process, nonrecoverable and not a crash-resume contract. DP can read its
own append prefix before final seal via a private builder API with explicit
committed-row count; flush the append buffer before a cache miss into that prefix.
Nobody else can open that unsealed table. Final table seal checks count/length.

### 5.2 Bounded ownership and run compaction

Use a private TempDir and exclusively created NamedTempFiles, 0600 files and
0700 workspace on Unix. Do not invent reusable names, follow existing symlinks,
or scan unrelated temp roots. One owning handle per live candidate run; do not
automatically keep a NamedTempFile **and** an uncounted reopened File. The
NamedTempFile handle can service sequential/random reads through private mutable
I/O state with seek-before-read. No arbitrary path reopening is needed on this
new path. Existing source-index TempPaths require identity-checked counted opens.

Bound candidate run metadata with a **64-level binary carry set**, at most one
run per level plus incoming+replacement (66 peak files). Level counts flushed
chunks, not deduped rows, so a duplicate-heavy merge still promotes correctly.
At a level collision, merge the two runs, exact-dedup if appropriate, seal,
drop both inputs, carry upward. Overflow of chunk counter/generation is explicit
TempBudgetExceeded; never dynamically add levels. This is O(R log R) merge work,
unlike repeatedly merging one giant run with each new small run. It is also
easy to prove/test. The 64 levels are a numeric bound, not an allocated Vec per
candidate. Per-file cleanup owners charge a fixed, length-independent control
reservation (owner slot, box/`Arc` headers, allocator envelope, deferred cleanup
slot). Only their pathname bytes and the cached resolved parent are file-pathname
processing excluded from the working budget; fixed descriptor charges and a
capped slot table remain charged working control state.

All live level-run handles are counted. Default handle policy supports the full
set; at a lower cap, use reserved emergency merge slots to collapse **two sealed
live runs before opening the next file**; track combined logical chunk weight,
allow non-power-of-two levels in pressure mode, and use a fixed slot priority by
weight/generation. Normal case remains binary carry; pressure may increase I/O,
not alter sort or dedup semantics. If two inputs plus replacement and mandatory
handles cannot fit, fail explicitly. Do not silently reopen untrusted paths to
evade the FD ledger. This simple policy avoids an unbounded on-disk manifest or
complex file allocator for 0.2.

Merge engine supports fan-in 2..16: reserve output slot plus reader buffers and
headroom **before** opening inputs. Binary carries use fan-in 2; finishing may
batch up to min(16, available handles/buffers). Fixed [Option<Head>;16] scan or
heap (fully charged) is sufficient. Smallest tuple wins; equal triple rows keep
minimum ordinal. RAM run chunk sorts in place with sort_unstable_by, no stable
sort scratch allocation. No global hash table, path list, run Vec or file list.
Drop consumed runs promptly, but retain their temp charge until replacement is
sealed. Default fan-in is not permission for every subsystem to open 16 at once.

### 5.3 Pipeline stages and memory fast path

Generation sink owns one fixed-capacity chunk, allocated once with checked
capacity and reservation, no grow-in-place/replacement at threshold. At capacity
sort by triple, dedup, spill, reuse chunk. A small fixed associative exact-triple
cache may suppress duplicates across flushes: remember minimum ordinal; on a
lower external ordinal emit the new row too, on eviction simply forget. The final
merge still picks the min. No false-positive/hash-only suppression. Bounded
resident-only suppression is optional; never skip enumeration/extension itself.

Finish generation: complete the source-index integrity barrier (§6.1), then drop
source index/accelerators, flush last chunk if needed,
merge runs to a single triple store. If no spill, retain RAM triple store.
Validator first certifies canonical stream in original validation order. A second
pass builds interval-order runs, selecting minimum(src,ordinal) per (dst,len),
then end-order runs for WIS. Distinct lengths remain. Every stage may use RAM if
its entire **simultaneous** allocation fits its assigned cap; otherwise fixed
chunk+disk. Adaptive mode must not try an allocation that starves required
downstream workspace. Selection policy changes resources only, not ordering.

For small all-RAM WIS, preflight candidate+DP+selected capacities including
replacement peaks; use the same objective and tie algorithm as disk, then the
same store-facing writer. Public RAM normalizer remains an independent test
oracle. ForceSpill test policy spills even one-row chunks and DP/match/source
stores; ForceRam test policy fails rather than silently spill. Never use force
flags as ordinary user tuning required for correctness.

## 6. Finder changes and feasibility under pressure

### m0 representatives

O(input/region) representative vector must not remain mandatory. Use a lazy
RepresentativeCursor keeping one completed-region maximum `(hash,position)` and
next region id. At target t compute the next region's representative when its
`min((region_id+1)*region, eligible_starts)<=t`, then insert if position<t, with
the identical representative index as source ordinal. Regions that cannot yet
become visible need not be computed. Compute each region's maximum with existing
hash function and earliest-position tie. This preserves the precise visibility
test at m0.rs:229–236, including the final partial region. A two-pass spooled
representative table is an alternative if testing shows interleaved reads hurt;
do not keep a full vector. Test candidate sequence and ordinal equality, not just
archive size. Lazy preprocessing can change which physical read failure happens
first; document it as physical failure timing, not a semantic row-priority change.

### CDC boundaries

Replace per-block Vec by M1/M2BoundaryCursor with next() -> Result<Option<(u64,u64)>>.
Keep m1's window/hash and p position (trigger after incoming byte with chunk_len
p-last_boundary), m2's 256-byte predictor/previous/hash reset on trigger, EOF
residual, and block resets exactly. Digest/compare/index insertion occur in
existing boundary order. Since the block maximum is 1 GiB and min match can be
small, calling this vector 'only one block' is not a bound adequate for 256 MiB.

### fixed/m5/overlay

Refactor the emission seam rather than rewrite matching algorithms. Preserve
seed grid, fixed_targets, digest quantum checks, exact compare, backward extension
and distance visibility. Optional accelerators are all accounted and denied in
stages as existing tests exercise. Preserve m3 digest+exact checks even where
uniform byte runs allow a safe extension jump. Remove the duplicate cache-disable
condition at fixed.rs:899–904 only as local refactor fallout; sink pressure is
not a reason to discard a useful cache if reserved working set already fits.

m5 and m0 can enumerate extremely many source/target pairs even when emitted
triples collapse. Offload removes RAM growth, **not** that time complexity. Cache
exact triple results only after independent extension; do not add uniform target
skip, unchanged-visible-source skip, source-grid pruning, dominance or candidate
caps. Existing exact LCE paths should be retained for small sparse fixtures.
Time infeasibility is a release risk to measure; a safe, proven enumeration
accelerator would need a separate reviewed change, not a silent approximation.

### 6.1 Required I1 private source-index query replacement

Use a private `CodecCandidateIndex` implementing the existing CandidateIndex
query/insert semantics; F1 calls `new_codec_candidate_index(session)` instead of
the public Hybrid constructor. Do not retrofit weaker validation into public
`HybridCandidateIndex`/`Run::collect_key_matches`. I1 owns the implementation in
candidate_index.rs and its unit tests; B0 owns the factory/session contract.

**Queryable immutable runs:** retain decoded IndexEntry fields and ordering, but
wrap private source runs in an identity-bound paged envelope. S1 owns the shared
envelope/checksum helpers; I1 owns source-entry payload decoding and search.
Use the §5 128-byte header, new private kind `SourceIndex=5`, order `source-query`,
record length field=104 (fits u16), kind-defined page width 64 KiB; count is entry
count, payload bytes is ceil(count/629)*65536. For this paged kind ONLY, payload
length is not count*record_len; the decoder explicitly dispatches on kind. A page
has a 32-byte prefix (u64 page_id, first_entry_index, valid_count, reserved=0),
629 legacy 104-byte IndexEntry slots (65,416 bytes), 72 zero padding bytes, and
16-byte BLAKE3-128 page checksum. Last page unused slots zero. Checksum domain
`SREP-OFF-SOURCE-PAGE-v1\0` includes session/file/generation, page prefix and
payload/padding. Expected first_entry_index=page_id*629; valid_count must equal
min(629, header.count-first_entry_index). Fixed page addressing needs no growing
RAM fence/offset table. Header count/length/identity are held in the run descriptor;
record checksums plus page identity detect swapping records/pages/files.

On seal, do one uncached sequential verification of all pages/entries and global
`index_entry_order`, and save an ordered whole-file BLAKE3-256 digest in the
bounded trusted run descriptor. Thereafter the library never writes a sealed run.
Keep its owning handle (counted; at most 16 source runs), not an open/path lookup
per target. Query epoch boundaries (before target loops, after checkpoint and
reopen if any) recheck header and exact physical length. Per-page cache misses
read/verify the whole page including records and bounds; cache hits use the
previously verified immutable in-memory bytes, not a boolean claiming the disk
has not changed. No mtime trust, per-page bitmap of unbounded size or checksum-only
membership oracle. Read errors/checksum failures are terminal, not no-match.

**Query:** binary lower_bound on decoded `(kind,key)` through a shared fixed
64-page (4 MiB) source cache, then stream the equal-key range. Skip positions
>=before; stop within the descending-position range when outside max_distance.
Seek only logarithmically many pages plus result pages, not all records. Ordinary
codec inserts have strictly increasing globally unique source position/ordinal,
so an IndexEntry identity cannot recur across source runs; test/assert this private
factory invariant. Each run's hit cursor is already in required descending
position/ordinal/metadata order. Merge up to 16 run heads plus the memtable head
with a fixed array, emit one at a time; never materialize all hits or re-sort the
whole source index for a query. No query fallback that replays callbacks. If a
future codec producer needs repeated identities, it cannot use this private
invariant without adding exact bounded identity-group reduction; use the unchanged
public implementation until separately reviewed. Current m0/CDC/fixed/m5 sources
are each inserted once, and overlay creates a new index.

**Bounded exact-negative accelerator:** maintain one 4 MiB bitset over all source
keys ever inserted in this finder index (including RAM and every disk run), six
positions derived from the complete kind+key: BLAKE3 of
`SREP-OFF-SOURCE-KEY-v1\0 || kind:u8 || key_len:u8 || key_bytes`, then take six
consecutive LE u32 words from digest[0..24], each modulo bit_count. Fix that domain
and byte encoding in tests; hash metadata/position is deliberately excluded since
membership is by query key.
Set bits before insert becomes visible; failure aborts the operation. Bits are
never cleared, including compaction; reset only with a new empty index. A negative
means no key ever inserted and skips memtable/run searches; a positive MUST still
do exact key/byte checks. Hash collisions only add work, never omit matches.
This is not candidate deletion or a hash-only positive match. Disabling/saturating
the filter leaves exact query behavior unchanged. It is an in-memory owned filter,
not a trusted unverified disk Bloom file; no per-run bitsets. Low-memory policy
reduces/omits it and the page cache deterministically; default large-fixture gate
requires the stated cache/filter reservations. Input bit flips/memory corruption
are outside this disk-integrity fault model just as for baseline RAM arrays.

At a run retirement/replacement, make a **fresh uncached complete read** comparing
header, length, ordered entries, page checksums and saved whole-file digest before
destroying that run. Merge consumption can supply this verification if every
byte is freshly read and checked, not served from cache; otherwise use a separate
pass. A replacement cannot become visible until its inputs pass. At successful
finder finish, `finish_verified(self) -> Result<SourceIntegrityComplete>` freshly
verifies all remaining runs, drops handles and returns a private completion
token; the codec cannot progress to candidate validation/publication without it.
Before overlay, verify/drop the base index; verify overlay index at its end too.
The token has private fields; B0's combiner requires both base/overlay tokens
where configured and hands only the combined EnumerationSummary to codec. Public
external-candidate compression uses a separate no-source-index entry route, not
a fabricated token. No generic Drop implementation can substitute for this
fallible explicit finish: failure must propagate before output.
All source files are then retired, so no retained source file can mutate between
this barrier and output. On failure abort, discard candidates and clean up; no
need to scan every other corrupt file to prefer its error over the terminal one.

**Detection promise:** persistent mutation since seal of a never-queried page,
including a page hidden by a negative filter result, is detected at retirement or
finish before public output. Mutation of a cached page on disk may be detected
only at that barrier; eviction/reload detects it sooner. Persistent header/length
changes are caught at epoch checks or barrier. No claim detects a hostile mutate-
and-restore race or guarantees next-query rejection of untouched bytes; these
cannot be proved with bounded cached reads. The saved digest also detects a
valid-checksum byte replacement relative to the sealed contents at the barrier.
Map private source corruption to baseline source-index CorruptIndex. This explicit
private timing change needs review acceptance; final success cannot hide durable
source corruption. See §3 for changed timing versus preserved semantic priority.

Working resources are preallocated before snapshot: source page cache 4 MiB,
global membership bitset 4 MiB, merge/sort/control workspace 8 MiB and memtable
<=32 MiB (in addition to separate candidate sink). The query owns only <=17 heads
and logical row positions; candidate spill may nest with these and <=16 source
handles still live. Reserve candidate emergency merge handles before query, not
after callback starts. FD pressure must compact/reduce the source run set before
entering a query, not suspend halfway and restart it. Low limits that cannot hold
minimal coexistence fail explicitly. Counters: source_query_count, negative_hits,
positive_queries, key_comparisons, page_loads/bytes, cache_hits, entries_yielded,
seal_scan_bytes, retirement_scan_bytes and barrier_scan_bytes. No 'validation'
counter that conceals all reads inside every lookup.

**Performance contract/tests for I1:** after sealing S bytes in r<=16 runs, Q
empty queries with filter disabled perform O(Q*r*log(entries_per_run)) page probes,
not Q*S bytes; with filter negatives they perform zero run-page reads. Full-scan
bytes are bounded by sum(newly sealed sizes)+sum(retired sizes)+sum(final live
sizes), independent of Q. Test repeated misses over a synthetic large run, cold
and warm cache, filter disabled/saturated, and injected key collisions. A test
fails if ordinary query calls Run::validate or the whole-index scratch fallback.
Also inject post-seal corruption on a probed page, unqueried page, cached page,
header/length, and an input being compacted; assert final public output untouched
and barrier failure for untouched corruption. Test a negative-filter-only workload
still reaches finish_verified and scans all remaining source runs exactly once.

### 6.2 Analytical workload envelope (not measured throughput)

Use separate quantities: Q target queries; P source/target pairs yielded for
exact confirmation; E qualifying candidates before suppression (ordinal advances);

U final unique triples; D distinct positive `(dst,len)` intervals; K selected.
`K<=D<=U<=R<=A<=E<=P` for finder output (empty/filtered cases allowed). Public
external iterators have A/raw rows instead of P. Input length L is never N.
Record counts and per-phase bytes are required for every hot row; do not infer
P, R or validation work from small final D/K.

For that all-zero m0/m5 model V< L²/2, about 34.4 GB at 256 KiB, 137.5 GB at

are pessimistic bounds, not expected totals for pinned fixtures. Sparse markers,
order1 phases, shifted repeats and tree blocks require actual canonical counts;
do not pretend all-zero equivalence proves their entire extensions equal.

Practical first implementation retains exact LCE and digest caches, reuses
validation read buffers/source pages, checks exact triples once after merge and
uses bounded post-extension triple suppression. I1 eliminates whole-run-per-query
work and whole-index hit fallback. No N² enumeration speedup is claimed. F1/T1
must instrument each hot fixture first and report E/A/R/U/D, V, source reads and
sort I/O against §10.2 before choosing adequate TMP; a not-completed row remains
release-blocking. If candidate extension/validation alone remains prohibitive,
require a separately reviewed exact accelerator/proof (full-byte established
period/equality, collision tests and ordinal parity), not a seed-based skip or
a declaration that disk offload was sufficient. The 72-row gate is unchanged.

For the **258 MiB required default-m3** fixture: source grid512 gives about
528,384 possible source positions; a 32 MiB memtable at illustrative
size_of(IndexEntry)=96 holds 349,525 entries, spilling around 178,956,800 bytes
(170.67 MiB). Remaining ~91,575,808 target queries times a ~36.35 MB run would

this is a hashing-distribution estimate, **not a correctness or worst-case bound**.

binary-search fallback. Required large-run telemetry must verify the removed

sum leaf writes plus merge reads/writes is <=64*R*(1+2*ceil(log2(max(1,C))))

can exceed this balanced estimate. Validation uses V; WIS storage uses D; source
index scans use sum of run versions, not Q times size. All are different metrics.
Analytic envelopes expose the remaining cost without requiring a long run in G2.

The >256 MiB all-zero stress case is not analytically feasible by naive exhaustive
m0/m5 enumeration: at 258 MiB the scales are ~5.72e14/~1.43e14 pairs. Even fixed
methods can have enormous equal-key enumeration. Keep the large stress gate as
an explicit unresolved release requirement, not a promised fast test or a silent
skip; coordinator must assign/review an exact accelerator if that gate requires
completion on those methods. Do not confuse this risk with the bounded indexed
query solution for the nontrivially unique required default-m3 258 MiB fixture.

## 7. Disk WIS and exact tie handling

Inputs: end-order candidate table C[0..N), random access by u64 row number.
Here scheduler-local N equals D in the §6.2/§10.2 accounting, not E/R/U.
One append-only DP table D[0..N) with fixed record size above; best[0]=zero is
implicit. D[i].best stores best[i+1], D[i].include_parent stores the winning
prefix chain tail used when considering C[i]. This avoids a separate O(N)
predecessor allocation or a third file.

For each i:

1. Binary-search C[0..i) for upper_bound(end<=C[i].dst), producing prefix count p.
   p=0 -> zero schedule; otherwise read D[p-1].best.
2. Include score uses checked u64 additions in gain, covered, count order exactly
   as baseline. Parent=previous.best_node; include depth=previous.count+1.
3. Exclude=D[i-1].best (zero at i=0). Compare objective; ties use algorithm below.
4. Append D[i] with chosen best and include-parent/depth, including parent even
   if include loses. Current include can be a stack row during comparison; earlier
   parents already exist. Commit row before next iteration.

Candidate corruption fails CorruptRecord; malformed DP indices/depth/count/order
fail CorruptIndex with offload-stage context. Require parent<i and parent depth
one less; best_node<=i and score/count sane; checked seeks/multiplications.
No default-to-zero corruption handling. N and sentinel range are checked before
append, and no saturating score arithmetic. Spool limits imply real disjoint
coverage cannot exceed input length, but do not rely on that to remove checks.

### 7.1 Constant-memory O(depth) lex comparator

Objective ties have equal count, hence equal-depth chains. Walk both tails
backwards **in lockstep**, comparing candidate tuple keys. Keep one variable
`earliest_difference`: whenever keys differ, overwrite it with their ordering.
The last differing position encountered in the reverse walk is the earliest
forward difference, therefore decides forward lex order. If node ids become
equal, remaining prefix is shared and cannot change the recorded difference;
stop immediately. If both chains end without difference choose exclude.
Validate depth/link invariants on the way. Equal key at different nodes is not
shared-prefix proof: continue. This is exact even when the same suffix keys occur
after a different prefix. It eliminates baseline's repeated walk from tail to
each forward position, reducing one tie from O(depth²) to O(depth) reads with O(1)
scratch. No chain Vec, probabilistic hash comparison, prefix rank or binary lift.

Use fixed page cache for candidate and DP rows (64 KiB pages; per-row integrity
when decoded). Default 64 pages each =8 MiB total plus bounded tags/append pages;
low-memory minimum 2 pages each. Cache keyed by full store identity and page id;
clock/direct-mapped deterministic eviction affects cost only. Dirty data is only
the append page; immutable pages need no writeback. Maintain validity lengths
for last page and reject short reads below committed prefix.

Rows (notably 96-byte DP rows) can straddle 64 KiB page boundaries. Assemble one
row into a fixed 96-byte scratch array from at most two pages, validate checksum,
then decode; never assume record/page divisibility or serialize padding between
rows. File offset is checked `128 + index * record_width`.

Optional bounded pair cache for proven tie comparisons: e.g. 4096 fixed entries
of `(node_a,node_b,Ordering)`; full identifiers/depth checks, no hash-only match,
never store incomplete comparison after I/O error. At most a fixed reservation;
miss falls back to exact walk. This plus shared-prefix early stop should handle
many routine ties. O(N*depth) across adversarial ties can remain; instrument
tie count, traversed nodes and page reads. Binary lifting/persistent ranks are
deferred pending measured need and proof, not required to claim correctness.

### 7.2 Backtracking without selected-index Vec

Walk winning final tail once, append candidate indices to reverse-index table.
Verify strictly decreasing predecessor indices and expected depth; its length
must equal final best.count. Release DP/cache when no longer needed. Read this
table from last row to first using a fixed page buffer; fetch C rows and append
Matches in ascending destination order with origin ids 0..K-1. Compute checked
coverage/literals, validate nonoverlap. Produce SelectedStore (RAM if bounded,
otherwise Match table). Release reverse-index table and candidate table before
writer source sorting. No whole-chain materialization or final global sort is
necessary because disjoint positive intervals are already ordered. Tests compare
every selected Match and both statistics with the unchanged small RAM oracle.

## 8. Writer store adaptation and archive identity

Prepare/validate SelectedStore before constructing the staged archive. Preserve
header construction, effective_min and max_distance validation order. The writer
should never call as_slice(), collect(), or make an O(K) Vec on the codec path.

* **Index:** destination cursor carries one match crossing a block; copy only
  uncovered ranges in exactly existing order, then block CRC. After body,
  compact_index_len replay computes checked ULEB count+gaps+distances+lengths;
  write_compact_index replay emits those exact bytes. Retain same locator checks.
* **Future:** external-sort full Matches by `(src,dst,origin_match_id)` (not merely
  src; not length). Full rows avoid random lookup via an O(K) source index. For
  each source block [start,end), save first row number, scan to first src>=end,
  calculate count, emit count, seek to first and replay that range. Alternatively
  two logical cursors share one table handle. This needs O(1) block metadata even
  when millions of sources fall in one block. Source exactly at end belongs to
  next block. Register fields remain source_offset, distance, **total** len.
  Destination cursor independently emits literal gaps. Verify final consumed
  source-row count. Source store plus SelectedStore are the only O(K) stores.
* **I/O:** preserve literal tags/ULEBs and full-match tag once at original dst,
  carrying remainder across blocks without additional match records. Keep one
  lookahead Match and carry u64, not a match-index-sized array. Adjacent matches
  remain separate; don't merge literals differently across block boundaries.

All layouts hash plaintext by existing block boundaries, encoded bytes in current
physical order, then same tail prefix, plaintext digest and encoded digest.
Reuse format_v3 routines untouched. Do not change NGv3 version or emit spill
provenance/ordinals. CompressionStats count semantic matches, not internal runs,
carry fragments or replay operations. Empty stores/layouts/checksums retain exact
known archives. Clone offsets: File::try_clone shares file position; use explicit
seek-before-read or independent counted handles, never assume independent cursors.

## 9. Reader and public API boundary audit

`v3/reader.rs::decode_archive` stages reconstructed output and builds History.
Index always calls `parse_index` -> BudgetedVec<Match>, including verify/info when
collect_matches=false; `decode_index_block` consumes that slice. Future's
`decode_sequential` has growing `future_regs`, `active_collectors`,
`active_destinations` heap, `free_registers`; FuturePeriod can spill bytes but
active metadata stays RAM. I/O is streaming except optional inspection metadata.
`inspect_matches` returns InspectedMatches with as_slice()/Deref and intentionally
requires full RAM. Do not claim that API is magically disk-backed.

This implementation plan guarantees bounded **compression** under declared RAM,
temp and handles. Existing decoders are still budget-enforced and may fail on
huge selected/active metadata; they are not an unbounded uncharged backdoor in
compression. Mandatory fixed 72 and 258 MiB roundtrips still must pass unchanged
decoder resource settings; selected rows K<=input_len/max(26,effective_min), far
smaller than raw N, makes that plausible, not proven here. Report decoder failure
as release-blocking, not compression success. If those gates expose it, assign a
separate reviewed reader work unit; do not let writer owner modify reader silently.
Possible bounded Index adapter is a full structural validation pass using
IndexCursor, then a replay for reconstruction (retains validation-before-body
error precedence), while inspect_matches alone collects. Future metadata needs a
separate design, not a casual reuse of a sequential MatchStore for its active heap.

## 10. Resource ledger and operational policy

### 10.1 Memory and preallocated working sets

The configured default remains 256 MiB. Budget all owned variable allocations,
fixed source/page/I/O buffers, merge heads, run/control metadata, checksum
state and cache tags. File pathname processing is deliberately excluded from
managed working memory: pathnames, `PathBuf`/`OsString` allocations and the
current-directory query are pathname processing, so their length does not
consume the `--memory` working budget and an over-long platform pathname fails
only as an ordinary OS I/O error, never as a custom memory-policy rejection.
Directory and per-file cleanup owners still charge their fixed inline control
state (owner value, box/`Arc` headers, allocator envelope, deferred cleanup
slot), which is length-independent. Distinguish ledger high-water, actually
allocated bytes and OS RSS. OS page cache, loaded executable/library mappings,
allocator bookkeeping, caller-owned input/output/iterator allocations and other
process threads cannot be strictly capped by this library; publish them as
measured overhead, never pretend ledger==RSS or promise arbitrary-process
RSS<=256 MiB. Additional resident memory beyond `--memory` can therefore come
from pathname processing, runtime and allocator overhead.

Default generation working-set plan: 4 MiB candidate chunk/cache; 8 MiB source
query/merge workspace plus 4 MiB source page cache and 4 MiB global key bitset;
source memtable capped at 32 MiB on codec path; 4 MiB
fixed runtime/control/serialization/FD metadata allowance. Reserve these before
optional accelerators. Chosen implementation: allocate mandatory fixed buffers
and the fixed-capacity source memtable on the parent MemoryBudget before optional
acceleration. A codec-only memtable flush clears/reuses that allocation rather
than replacing it with an empty Vec; direct query and scratch transforms use the
preallocated query workspace. No child budgets: every reservation remains on
the same parent, no detachable lease lifetime or double accounting. Fixed stack
and control allowances reserve only the memory not already charged as a buffer.
BudgetedVec needs a crate-private clear-with-capacity operation from B0; I1 must
not implement a second memory ledger. Public source-index constructors retain
their adaptive behavior; its private session constructor uses the fixed workspace.
Expose scratch workspace lending through a scoped exclusive borrow: nested
candidate emission uses its separate preallocated sink workspace, never the
source-index workspace still borrowed by the query. This is a required B0/I1 seam.

At less than default memory choose deterministic smaller chunks/caches, never
smaller semantic search. Minimum streaming workset target 2 MiB (source caches,
two-way merge, two pages per random table, counted fixed/control stack allowance).
If it cannot be reserved, report MemoryBudgetExceeded before output; no promise
that every 2 MiB config succeeds with all method params. Fixed arrays living on
stack need a simultaneous-liveness audit and reservation too; do not count only
heap. Small shared functions must not each reserve an entire 4 MiB allowance.

After generation, drop accelerator/index leases; normalization can use 8 MiB
sort chunks and 8 MiB random caches, bounded tie cache and output buffers. Writer
uses fixed buffers plus capped sort chunk/source stores. At transitions old+new
store coexistence is charged. BudgetedVec's old+new peak cannot be eliminated by
shrinking its logical len; fixed chunks are reused, and actual capacities checked
after allocation. No unaccounted HashMap, Vec growth or per-row String telemetry.

For accelerator feasibility include transient suffix sorting arrays, reverse
bytes and tree power-of-two rounding, not just retained inverse/tree. Keep
InputSnapshot's staged memory-denial fallbacks. FixedAcceleration costs roughly
9 bytes/input-byte before digest/hash caches, with exact size_of accounting;
optional caches use actual Option element size, not a guessed 8/16 bytes. Preserve
working headroom rather than allowing a successful snapshot to starve its finder.

### 10.2 Handles, files, I/O and physical temp space

Private OffloadPolicy defaults: 128 accounted open handles including a conservative
4-handle external allowance (caller input/output plus standard/log overhead),
192 live temporary files, single-file cap=min(temp_limit, i64::MAX), cumulative
scratch read+write policy `Unlimited` with checked u128 telemetry (finite limits
available in test/private policy), max fan-in 16. These are independent units;
do not stuff FD or I/O into TempBudget. Default total temp remains 4 GiB; required
large-candidate gates may document adequate larger TMP budgets without increasing
memory. Finite I/O test policy checks before an operation; no unconditional I/O
cap low enough to reject exact duplicate-heavy runs. Counter overflow fails
explicitly rather than wrapping.

The cumulative I/O policy includes final output-transfer bytes as specified in
§10.4 in addition to scratch reads/writes. Telemetry separates those categories.

Every open/clone/reopen acquires an FdLease first, released after closing handle.
Every owned temp file has FileLease and TempBudget reservation; partial writes
remain charged until truncated/removed. Reserve peak growth before write; on
failure restore logical state and drop contaminated builder. Source index paths,
input spool, CLI output allowance, query reader, sink compaction, DP, backtrace,
writer input clones and staged archive share one session policy. Public callers
can supply arbitrary Read/Write objects hiding handles; count allowances, not
uninspectable caller internals. Multiple public compression operations each have
their own policy; no claim to a process-wide OS limit across concurrent callers.

Default generation upper accounting check: up to 66 candidate run handles,
private source runs <=16 owning handles plus merge output/one verifier <=2,
input owner/readers <=4, external allowance 4, reserved control/emergency <=4:
under 128. Query cursors reuse source handles; they do not open 16 more handles.
Actual measured nesting replaces this conservative sketch during integration.
Public source RunSet TempPaths do not hold all their handles open; private codec
source runs do (§6.1). At most 16 live source-run descriptors, but checkpoint
scratch sets may coexist. File cap must count
all old/new source scratch sets and candidate sets, not only open files. If
measured code exceeds 192, fix lifetimes or revise policy explicitly with review.

Low-cap scheduling must protect two candidate merge handles plus replacement
before entering a source query callback. Candidate sort never requests source
index growth, avoiding a cyclic wait; operations are serial, reservation failure
returns an error, never waits holding half a merge's resources. At policy caps
such as 16/24, compact candidate levels earlier and batch source merges; test
both success where minimum fits and clean failure where it doesn't. OS EMFILE
from unrelated process handles remains TemporaryStorageFailure; don't assert
that a private cap detects every external OS limit portably without unsafe code.

**Corrected temp model (raw/per-run/unique counts MUST NOT be conflated):**
Use E,A,R,U,D,K as §6.2, and C flushed chunks, each with retained rows r_j after
local triple dedup; R=sum(r_j). U is only final globally unique triples. The same
U identities may reside simultaneously in many carry levels. Define
`F(n)=128+64*n`. At any generation instant the exact charged candidate-file bytes
are `sum(F(n_l) for live sealed levels) + incoming_file_bytes + replacement_bytes`,
including *both* merge inputs until successful replacement seal/retirement.
Count an incoming run only once if it occupies a live slot. Partial replacement
bytes stay charged on failure until deletion/truncation succeeds. A resident
chunk costs RAM, not file bytes until written.

For a level with represented chunk set J_l, `n_l<=sum(r_j,j in J_l)` and
`n_l<=U` if final U is known after the fact; level sets partition flushed chunks.
Thus sealed+incoming retained rows <=min(R,(number_of_live_runs)*U), NOT <=U.
A merge replacement has <=sum(rows of its selected inputs). With <=66 simultaneous
files, a simple generation bound is `66*128 +128*R` bytes; it counts up to two
physical copies of all retained leaf rows. A tighter event bound uses the actual
live sum plus selected input sum. For binary carries n_l<=min(U,b*2^l) with max b
locally retained chunk rows; pressure mode uses each descriptor's represented
chunk weight instead of 2^l. These remain bounded metadata, not a stored list of
all r_j. Keep checked aggregate retained-leaf weight per run and total R counters.

After global triple merge, later transforms consume each unique row once:
interval-sort phase <=input 64*U + output-generation 128*U (plus headers), then
end-sort <=64*D+128*D; if positive filtering reduces counts these bounds shrink.
Only at this **post-global-dedup** phase is a `3*64*U` estimate valid, never for
candidate generation. WIS is `64*D+96*D+32*K` at backtrace, then
candidate+reverse+64*K Matches after DP drops. Future source sorting keeps
destination Matches 64*K plus at most128*K output runs including replacement.
Exact source-index bytes S include paged headers/padding, old and replacement
versions and checkpoint scratch. Overall peak is input I + phase-specific S +
candidate/DP/output phase + staged archive Z + CLI sibling copy up to Z; take
maximum over actual overlapping phases, not a sum of all sequential stages.
For D=1,000,000 C+DP is160,000,000 bytes; this says nothing about earlier R.

Example capacity envelopes for hot rows: with no helpful bounded cache/local
dedup, R<=E<=P, so generation candidate bytes alone may approach128*P: ~275 GB
for a 512 KiB m0 all-key envelope, ~69 GB m5, ~35 GB fixed, ~619 GB sample12 m0.
These intentionally loose upper bounds are NOT 'adequate temp' recommendations
or expected measured sizes. They are not a prohibition on provisioning a larger
independently configured temp budget; RAM remains the primary bound and the
configured temp/file/FD/cleanup limits remain mandatory. Real capacity planning records R, maximum live-row
sum and merge input/output coexistence per hot row, then includes I/S/Z and a
documented margin. For planning before a completed run, use counts from a
bounded instrumented enumeration/counting pass or conservative prefix forecasts
with clear uncertainty; don't label final-U-based estimates adequate. Tests use
a cycling duplicate set larger than cache/chunk and cache-disabled mode so many
levels each retain the same identities, assert exact ledger peak and the R-based
bound, then fail replacement mid-write and assert both inputs remain charged.
R-based bounds may be pessimistic but cannot undercount duplicate-heavy runs.
Published CLI duplicates the archive during final copy; both copies consume temp.

### 10.3 Errors, cleanup, publication, cancellation

Keep public ErrorKind enum and exit codes stable: memory=13, temp=14, temporary
storage=16, output I/O=18, atomic publish=19. Private storage error category plus
context distinguishes FD limit, file-count limit, single-file limit, I/O policy,
run checksum, header identity, DP link corruption and cancellation. Map handle/
file/I/O limits to TemporaryStorageFailure; temp-byte/single-file capacity to
TempBudgetExceeded; internal record corruption CorruptRecord, index/header/link
inconsistency CorruptIndex. No new public enum variant without interface review.

Candidate generation, source integrity barriers, validation, WIS and layout
preparation complete before public copy, so errors **in those stages** leave
public output untouched. Storage remains involved during publication: baseline
`codec::copy_spool` maps read failures to InputIo and writes/flush to OutputIo.
A staged read may fail after prior chunks were written. Generic Write/stdout can
therefore be partial on InputIo, OutputIo, late integrity failure or cooperative
cancellation, not just OutputIo. CLI writes its sibling temp and persists only on
complete success; any such failure leaves the destination unchanged and removes
the sibling temp (subject to separately reported cleanup failure). Preserve these
error identities; do not remap a read failure into an output failure.

### 10.4 Known-length publication preflight and copy permit

B0 implements a private `prepare_publication(staged, session) -> CopyPermit`,
then `copy_staged_exact(staged, output, permit)`. L1 hands over sealed length Z
and a BLAKE3-256 whole-staged-file digest computed over exactly appended bytes
(including final digest/tail); private metadata only, no NGv3 format change.
Preflight rechecks file length and reserves, **before any public Write**, the
entire known remaining publication I/O envelope: Z for uncached staged integrity
pre-read, Z for final staged read, Z for final output writes, total checked 3*Z.
This session's I/O policy explicitly counts publication output bytes even for a
generic non-file Write; unknown caller-internal I/O is excluded. Debit output
bytes at the private copy loop, not inside the public BudgetedWriter: main.rs is
a separate binary crate and cannot receive a private CopyPermit through the
unchanged public compress API. CLI BudgetedWriter continues to enforce its shared
TempBudget independently (space, not cumulative I/O). That existing temp-byte
limit may still fail during copying into the CLI sibling temp, leaving the public
destination unchanged. Generic writer-owned capacity also cannot be pre-reserved
by this library. This change guarantees preflight of the **entire session I/O
policy** for final transfer, not arbitrary hidden writer limits or CLI space.

I/O accounting has separate `used_actual` and `reserved_remaining`: admission
checks used+all outstanding reservations+request<=finite_limit using checked
u128. Successful bytes transfer from reserved_remaining to used_actual once;
short reads/writes debit their actual returned count, Interrupted retries debit
zero. Abandoning/failing a permit releases unused reservation, not actual I/O.
Lower-level staged readers accept a private permit slice; the copy loop debits
public output once, and BudgetedWriter only charges temp space, so operations
cannot be double-charged to I/O. No new per-chunk finite-budget admission
can fail halfway through a correctly preflighted final copy. Session is serial;
other stages have finished, and any nested writer work must stay in its allowance.
Output write failure remains possible regardless of this policy reservation.

After reservation, make the uncached integrity pre-read and compare Z/digest,
rewind, check cancellation, then enter CopyStarted immediately before first public
write. Copy exactly Z bytes with bounded buffer; early EOF is InputIo with
staged-truncation context, not successful short copy. Hash bytes again during
copy; compare length/digest at completion and flush output. Reserve no unknown
EOF probe (known length + metadata length check suffices); metadata/checksum
computation does not debit byte I/O again. If file changes after preflight,
uncached read errors/checksum mismatch may occur after prior chunks, even after
all Z bytes were written. That remains an error, never successful stats; it is
impossible to guarantee rollback or early corruption detection for arbitrary
Write under post-preflight disk mutation. Late digest mismatch maps CorruptRecord
with staged-publication context. CLI still does not persist the sibling file.

Cancellation before CopyStarted leaves output untouched. Once started it is
cooperative between chunks and may leave a prefix, with contextual storage error;
there is no promise to atomically cancel stdout. Errors from output.flush or CLI
sync/persist follow existing OutputIo/AtomicPublish mappings. A generic writer
can have all bytes and still receive an error; output completeness is not success.
Fault injection must target the second staged read pass after the first public
chunk, not only the preflight read. §11 requires both API-prefix and CLI-destination
assertions. No native signal handling or new public cancellation API is added.

RAII cleans up ordinary errors and panic unwinding. Cooperative private test
cancellation is checked per chunk/merge/page and at bounded finder-loop intervals,
returns a contextual storage error, and drops all resources. There is no new
public signal/cancellation API here. SIGKILL/power loss cannot run Drop: orphaned
private workspaces may remain; never claim crash-cleanup guarantee. Document safe
manual removal of an identified abandoned workspace when no process uses it;
no automatic recursive deletion of guessed names or another active session.
Close/delete errors are recorded in bounded telemetry/log contexts, preserving
primary error; explicitly report cleanup failures rather than claiming zero disk
residue from counters alone. Same-user hostile path replacement is not a security
boundary of tempfile; use private directory and owned handles, no custom unsafe.

## 13. Risks, feasibility and exit criteria

Main complexity is not serialization: it is protecting working headroom during
source-query callbacks, preserving validation precedence, and avoiding an O(K)
writer reconstruction. This plan deliberately avoids disk B-trees, general file
manifests, persistent recovery, parallel merges and binary-lifting chains. The
storage backend is reusable but only four fixed row kinds are needed initially.
The private source index additionally uses one paged IndexEntry kind (§6.1), not
a generic database or a growing resident search directory.
Representative/CDC cursors remove two mandatory growth sources with small state.
The reverse lockstep comparator is simpler and asymptotically better per tie than
baseline; require its independent oracle proof/tests before using it.

Remaining measured risks: m5/m0 enumeration time on zero/sparse data; m3 long
default path without a full snapshot; source-page search/cache cost after the
required removal of whole-index-per-query scans and scratch fallback;
validation reads proportional to total canonical candidate lengths; pressure
compaction I/O amplification; existing decoder active metadata; actual platform
handle overhead and 128 policy sufficiency; temp disk capacity and final archive
duplication. A bounded algorithm may still be too slow or need more temp than
4 GiB. Do not substitute heuristic candidate removal or raise memory to pass.

Design completion is distinct from implementation completion. Implementation
acceptance requires every compression allocation/handle/file/I/O path accounted,
all semantic/byte/error parity tests passed, 72 rows and long gate completed with
default memory/documented temp, unchanged quality gates reported honestly, failure
cleanup/publication verified, and native platform evidence. Independent review
must specifically sign off the record identity checks, working-set ownership,
binary/pressure compaction metadata bound, tie comparator and raw API adapters.
