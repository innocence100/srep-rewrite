# Requirement traceability acceptance checklist

This document summarizes the machine-checked manifest in
`tests/requirements.json`. The manifest is authoritative: it contains all 515
extracted requirement IDs, canonical payloads, statuses, witnesses, and
evidence paths.

## Reproduce the audit

```sh
CARGO_TARGET_DIR=/tmp/opencode/srep-requirement-target \
  cargo run --locked --bin requirement-audit -- --check
```

The audit validates the reviewed specification SHA-256, extracted requirement
cardinality, canonical IDs and payloads, exact curated mappings, repository
relative evidence paths, and real Rust test names. `--write` remains a review-
gated manifest regeneration operation and must not be used to bless an
unreviewed specification change.

## Current status

- Extracted requirement population: **515** units (`extractor_version` 6).
- **363 active** requirements retain executable witnesses and checked evidence.
- **152 retired** requirements are drawn from an explicit, curated
  requirement-level list of genuinely obsolete NGv2-only wire rows: the v2
  archive header, record framing, record checksum domains, MethodParameters,
  LayoutMetadata, BlockDirectory, DataBlock payload schemas, IndexSection,
  ArchiveSummary, fixed Trailer, and the exact-v2 matrix assertions. Each
  retired row carries the single approved retirement reason and no active test
  witness. There is **no** heading- or section-range rule: a unit in section 10
  is active by default unless its exact ID is listed.
- Two mixed section-10 requirements stay **active** because their retained
  halves are NGv3-essential:
  - `REQ-8251cc2a92108692` (`10.0 Wire limits versus operational limits`) keeps
    the operational/resource limits (`output_limit`, memory budget, and the
    shared `temp_limit`); the obsolete wire-clause halves are documented, not
    retired as a whole. It points at `src/resource.rs` and the budget tests.
  - `REQ-be9f15856c6da519` and `REQ-9c1de6fb88dc4c57`
    (`10.10 Checksum IDs and implementation research decision`) keep the
    checksum IDs, implementations, CLI selector, and golden vectors. They point
    at `tests/checksum_vectors.rs`, `docs/checksum-audit.md`,
    `scripts/checksum-goldens.py`, and `src/checksum.rs` — never unrelated NGv3
    header tests.
- NGv3 wire behavior is covered by `src/format_v3.rs`, `src/v3/reader.rs`,
  `src/v3/writer.rs`, `tests/v3_acceptance.rs`, and the current semantic
  comparison scripts. Historical SuperREP v1–v4 behavior remains active and is
  covered by `src/legacy/` and `tests/legacy.rs`.
- Historical NGv2 specification text and frozen archive/hash pins remain
  provenance-only. They are not decoded or regenerated by production code.
- The current audit rejects any retired status whose exact ID is not in the
  curated list, rejects any retirement reason other than the single approved
  string, rejects retirement-policy section drift, rejects retirement reasons
  on active rows, and rejects active test witnesses on retired rows.

## Evidence interpretation

The current NGv3 comparison gates validate wire-independent candidate metrics,
match witnesses, NGv3 magic/version, round trips, and current archive metadata.
They do not compare current NGv3 bytes or sizes to retired NGv2 pins. Retained
historical NGv2 bytes are checked offline for their frozen hashes, headers, and
provenance only. No NGv2 compatibility claim is made.

The 0.1.0 package contract is limited to the Linux x86_64 glibc artifact
`srep-v0.1.0-x86_64-unknown-linux-gnu.tar.gz`. Its package root must contain
`srep`, `LICENSE`, `THIRD_PARTY.md`, `THIRD_PARTY.audit`, `README.md`,
`CHANGELOG.md`, and `NOTICES`; `SHA256SUMS` is external to the tarball. The
Linux preview binary is dynamically linked and observed GNU libc symbol
versions up to GLIBC_2.30 (a runtime symbol-version bound, not a distro
package name). Exact checksums are in `NOTICES` and `SHA256SUMS`. Windows and
macOS binaries are optional and are not promised by this preview.

Prior CI evidence at commit
[`8dca8be`](https://github.com/innocence100/srep-rewrite/actions/runs/34926545492)
covered six native jobs: Linux, Windows MSVC, and macOS ARM64 at stable and
Rust 1.88. This is source-validation evidence for that commit, not new Linux
artifact evidence. The retained m1 result used a 258 MiB input and included a
repeated block whose match-distance witness was greater than 256 MiB; it
completed in 17.57 seconds. It is not full round-trip evidence and is not
default-m3 performance evidence.
