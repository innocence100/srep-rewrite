### Resource facts (managed budgets, not RSS)

- `--memory` is managed compression working memory (buffers, candidate storage,
  indexes, sorting, WIS/match selection, caches, working control state). File
  pathname processing, runtime, and allocator overhead are **excluded**. It is
  not a cap on total process RSS.
- The CLI default temp limit is 4 GiB. The 72-row corpus used an explicit 32 GiB
  temp limit; the managed temp ledger peaked at 9646868416 B = 8.984346 GiB. The
  4 GiB default can fail this corpus (`TempBudgetExceeded`), so the 32 GiB
  allowance is a corpus-specific allowance, not a universal disk requirement.
- Derived `resource-summary-release.json` (SHA-256 `b601c549…`) reports max
  managed RAM peak 268435456 B and max managed temp peak 9646868416 B.

## Runtime requirements (observed, per published package)

- **Linux x86_64 glibc:** requires at least **GLIBC_2.34** as observed from
  GLIBC symbol versions. Built on Ubuntu. The prep host (glibc 2.31) could not
  load it; actual Linux execution was accepted inside an Ubuntu 24.04 container.
  This is an observed floor, not a guarantee for every environment.
- **Windows x86_64 MSVC:** native PE32+ x86_64 MSVC (`srep.exe`), unsigned.
  Not ARM64, not MinGW.
- **macOS ARM64:** native arm64 Mach-O (not Intel/universal); not publisher
  code-signed and not notarized. It carries an ad-hoc Rust code signature
  (`LC_CODE_SIGNATURE`, CodeDirectory flags `0x20002` / `CS_ADHOC`); an ad-hoc
  signature does not authenticate a publisher identity.

No other targets were built or tested for 0.2.0.

## Caveats and known limitations

- The release is a **limited prerelease**; `latest=false` and it is not the
  default "latest" release.
- The tag is unsigned (`verification.verified=false`, reason `unsigned`).
- The 512 KiB sparse sample 07 remains hours-level work for some methods. This
  is a known 0.2.0 release limitation. No future optimization is claimed.
- `release-provenance.json` still records `status: VERIFIED_PUBLICATION_CANDIDATE`
  because the hashed manifest was prepared before tag creation and was
  intentionally not edited afterward (avoiding a cyclic approval). The
  publication facts are recorded in the separate post-publication receipt, not
  by editing that manifest.
- The `README.md` and `CHANGELOG.md` embedded in each published archive are
  byte-frozen pre-publication snapshots at `6ce0a32`; the archives were not
  repacked. This repository's documentation is the current one.
- Old releases are preserved unchanged: v0.1.0 (id `394791284`, published
  2026-09-23) and v0.1.1 (id `399148285`, published 2026-09-29) remain as they
  were; no tags were moved and no assets were replaced.
