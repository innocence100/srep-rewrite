## What this release is

SREP-NG 0.2.0 adds the bounded-memory offload path for internal generation. It
does not change the NGv3 wire format or the matching semantics: exact
candidate/ordinal/full-chain WIS bytes and public APIs are unchanged. NGv3
remains the current read/write format; the software version is 0.2.0 and the
wire-format version is NGv3.

- NGv3 is read/write and self-contained.
- Historical SuperREP v1–v4 are embedded read-only inputs.
- NGv1 and NGv2 are rejected as `UnsupportedVersion`.
- Split indexes and sidecar indexes are rejected/unsupported.
- Compression defaults to m3 / index / xxh3 / 8 MiB blocks.
- Rust 1.88.0 remains the MSRV.
- Preserve the original input, test the archive, decompress to a new
  destination, and compare bytes before deleting or replacing source data.

## Managed-memory contract

`--memory` limits managed compression working memory: input/output buffers,
candidate storage, indexes, sorting, WIS/match selection, caches, and their
associated working control state. File pathname processing, runtime and
allocator overhead are excluded; it is not a hard cap on total process RSS.
Additional resident memory beyond `--memory` can come from those excluded
categories. In particular, `--temp-dir` is a pathname location whose length
does not consume the `--memory` working budget.

## Evidence status

Evaluation captures binary identity once (`binary_identity`: path, SHA-256,
`--version`) plus a dedicated `identity_probe` transcript, separately from
per-row command entries (`samples[].commands[method]`:
compress/info/test/decompress/xz, each with argv, exit code, stdout, stderr). A
failure persists an incomplete, non-passing report that retains completed rows
and the failing command's complete output, including timeout diagnostics from a
SIGTERM handler and any partial `.xzraw` artifact fact. Identity
changes/replacement/unavailability on disk are detected at row and final checks
and fail the report as `identity-recheck` / `identity-final-check`.

The records below are separated into **final actual-package evidence for the
published release** and **archived historical local candidate evidence**. They
were produced on different binaries and must not be conflated.

## Native packages and provenance

The native-release workflow defines six jobs: Linux x86_64, Windows x86_64
MSVC, and macOS ARM64, each at Rust 1.88.0 and stable. Each job checks the exact
source SHA on a clean checkout, verifies the manifest version (`0.2.0`), and
runs locked checks, tests, and packaging. The three MSRV jobs upload packages;
the stable jobs validate without uploading. For 0.2.0 both runs passed 6/6 on
`6ce0a32` (packaging
[`37939335761`](https://github.com/innocence100/srep-rewrite/actions/runs/37939335761),
CI
[`37939335813`](https://github.com/innocence100/srep-rewrite/actions/runs/37939335813)).
Artifacts are named `srep-v0.2.0-<target>` with `BUILD-PROVENANCE.json`,
`NOTICES`, and `SHA256SUMS` beside the archive.

Published packages and observed runtime requirements (details and hashes in
[`docs/evidence/v0.2.0-publication.md`](../evidence/v0.2.0-publication.md)):

- Linux x86_64 glibc: observed GLIBC_2.34 floor.
- Windows x86_64 MSVC: native PE32+ MSVC, unsigned (not ARM64/MinGW).
- macOS ARM64: native arm64 (not Intel/universal); not publisher code-signed
  and not notarized. It carries an ad-hoc Rust code signature
  (`LC_CODE_SIGNATURE`, CodeDirectory flags `0x20002` / `CS_ADHOC`); an ad-hoc
  signature does not authenticate a publisher identity.

No other targets were built or tested. The package-embedded `README.md` and
`CHANGELOG.md` are the frozen pre-publication snapshots from `6ce0a32`;
archives were not repacked after publication.

### Release-time timing policy

Per explicit user approval, the six wall-clock budgets in
`tests/fixed_performance.rs`, `tests/m5_performance.rs`, and `tests/m0.rs` are
release-time gates: each is guarded by `if !cfg!(debug_assertions)` and enforced
only in the optimized profile, with the original numeric limits unchanged
(m3 < 120 s, m4 < 180 s, m5 finder < 30 s, m5 2 MiB far distance < 180 s, m0
repeat < 5 s, m0 exact-repeat < 30 s). Debug-profile runs still perform and
assert every correctness, oracle, round-trip, exact-fixture, hash, and resource
check, but do not fail on elapsed time. This is a policy clarification, not new
evidence: it neither claims nor rewrites the historical ordinary-CI debug
results, and the release-profile native gate remains the place where the timing
limits must actually pass. The ordinary `ci.yml` debug jobs keep their existing
commands and serialization.
