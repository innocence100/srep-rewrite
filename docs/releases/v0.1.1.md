# SREP-NG 0.1.1 maintenance release notes

**Status: source and tooling candidate; publication requires parent review and
the native GitHub Actions run.** This document does not publish a release and
does not alter the existing `v0.1.0` tag or assets.

## What this release is

SREP-NG 0.1.1 is a maintenance release for cross-platform distribution and
release tooling. It does not change the compression algorithm or make an
algorithm-quality claim. NGv3 remains the current read/write format; the
software version is 0.1.1 and the wire-format version is NGv3.

- NGv3 is read/write and self-contained.
- Historical SuperREP v1–v4 are embedded read-only inputs.
- NGv1 and NGv2 are rejected as `UnsupportedVersion`.
- Split indexes and sidecar indexes are rejected/unsupported.
- Compression defaults to m3 / index / xxh3 / 8 MiB blocks with unchanged
  resource semantics.
- Rust 1.88.0 remains the MSRV.
- Preserve the original input, test the archive, decompress to a new destination,
  and compare bytes before deleting or replacing source data.

## Native packages and provenance

The candidate native-release workflow defines six jobs: Linux x86_64, Windows
x86_64 MSVC, and macOS ARM64, each at Rust 1.88.0 and stable. Each job checks
the clean source checkout and locked all-target build/test path. The MSRV job
also packages and extracts a native artifact, then verifies:

- actual compiler version/commit/host and Rust copyright notice;
- Cargo registry license/copyright notices and `THIRD_PARTY` files;
- source SHA, tooling SHA, binary SHA-256, archive SHA-256, and extracted hash;
- extracted `--version` and `--help`;
- empty and multi-block compress/info/test/decompress/hash round trips.

On push, the workflow binds both source and tooling to the run's `github.sha`.
Manual dispatch requires a source ref, expected full source SHA, and version,
and records tooling separately at the workflow SHA. It does not hard-code the
historical 0.1.0 source commit. New runtime compatibility is
unknown until the corresponding native build completes. Linux cross-linking is
not used as Windows/macOS evidence.

Expected names are:

```text
srep-v0.1.1-x86_64-unknown-linux-gnu.tar.gz
srep-v0.1.1-x86_64-pc-windows-msvc.zip
srep-v0.1.1-aarch64-apple-darwin.tar.gz
```

Exact files, hashes, compiler, and runtime information must be read from each
artifact's `BUILD-PROVENANCE.json`, `NOTICES`, and adjacent `SHA256SUMS`.

## Release-body proposal — not publication authorization

Use the scope, limitations, defaults, safety advice, and history mapping above
in full; do not shorten away existing limitations. Before publication, append
the exact candidate/source/tooling SHA, six-job native run URL, three artifact
hashes, binary hashes, and observed runtime requirements from the new packages.
Do not reuse the old GLIBC_2.30 bound for a new Linux binary. Windows is native
x86_64 MSVC; macOS is ARM64, not Intel/universal. These packages are not publisher
code-signed or notarized; macOS may require explicit Gatekeeper approval after
verification. The README supplies checksum, extraction, and first-run commands.

No new native run, clean-commit package, or 0.1.1 runtime measurement is claimed
by this source-review proposal. The separate debug Windows timing failure
reported in prior CI is not fixed here; release-profile evidence must not be
represented as debug-profile validation. No unsafe uniform-skip experiment is
part of this release or its fidelity evidence. The 0.2 memory work is separate.
