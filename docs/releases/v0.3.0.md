## Development changes

- `srep compress` automatically resolves memory and temp limits if each flag is
  omitted. Each explicit `--memory` or `--temp-limit` controls only that resource.
- The managed-memory budget is based on half total physical RAM, bounded by
  identified visible hard limits. Linux reads `MemTotal` and visible cgroup v1/v2
  memory limits. Indeterminate or unavailable detection can choose a conservative
  fallback and report its actual bytes on stderr.
- Automatic temp limit is `max(32 GiB, regular_input_length × 10)` for regular
  file input, and 32 GiB for stdin/non-regular input. Checked multiplication
  overflow fails before output staging and requires an explicit temp limit.
- Other CLI commands and library `ResourceConfig::default()` remain 256 MiB
  memory / 4 GiB temp. Matching algorithms, archive format, and atomic publication
  are unchanged.

## Limitations and acceptance boundary

This is a best-effort *budget selection*, not a hard memory cap or availability
guarantee. It does not account for competing physical-RAM users, hidden cgroup
ancestors, RLIMIT_AS, Windows Job Objects, or macOS container limits. Linux hosts
with unreadable/missing expected visible cgroup files may conservatively fall back;
the current local Linux host has taken that fallback path in the recorded smoke
run. Half-physical-RAM behavior is covered by injected resolver tests, but this
host observation is not evidence of a production run with that origin. These
limits cannot be represented as globally enforced policy.
